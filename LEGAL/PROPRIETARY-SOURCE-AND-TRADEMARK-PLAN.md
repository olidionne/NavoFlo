# NavoFlo proprietary-source and trademark plan

Draft: 2026-08-20.

## Source-code posture

- Keep commercial C#/.NET add-in source, licensing server, signing pipeline,
  customer-specific mappings and future Analyzer server code in private repos.
- Publicly distribute only the binaries, documentation and open-source notices/
  source material that the applicable licenses require.
- Do not embed API keys, payment secrets, signing keys, database credentials or
  entitlement signing secrets in Navo2D/Navo3D browser code.
- Treat published source as no longer secret even though copyright remains.

## NavoFlo / NavoBase / NavoPro names

Before paid launch or significant branding spend, perform a formal trademark
clearance in the intended markets (at minimum Canada; add the United States and
other markets before entering them). Do not assume a name is clear only because
its domain or corporate name is available.

## SOLIDWORKS references

Use SOLIDWORKS only descriptively (for example, “add-in compatible with
SOLIDWORKS”) and use NavoFlo/NavoBase as the actual product identity. Do not use
SOLIDWORKS logos, partner badges, certification marks, or wording that implies
Dassault Systèmes endorsement unless written authorization has been obtained.
Consider the SOLIDWORKS Solution Partner Program when the add-in is commercially
ready and customer references are available.

## Autodesk / AutoCAD references

AutoCAD may be used internally as a behavioral reference for CAD conventions.
The shipped NavoFlo UI, icons, branding, documentation and marketing should
remain visually distinct and should not claim affiliation, certification or
endorsement by Autodesk.
